# 记忆与规则：把踩过的坑变成制度

> 同一个坑踩第二次的时候，问题通常不在智能体够不够聪明，而在流程里没有东西把它记住。这半年形成的一个固定动作是：凡是重复出现的问题，都从"这次怎么解决"升级成"下次怎么不用再解决"。

::: info 先说结论
- 规则文件写环境约束，记忆文件写已有结论——两者分工清楚，才不会写成一锅介绍；
- 需求会散落在几十上百个会话里，**让智能体回查自己的历史**比人工回忆准确，但汇总结果必须带"状态"字段；
- 一条经验只有放进"每次都会被读到"的位置（规则文件、检查清单、脚本）才算生效，写在聊天记录里等于没写；
- 判断标准只有一句：下次遇到同样的事，它会自动起作用吗？
:::

## 一、需求总账：让智能体回查它自己的工作记录

会话数量累积到上百个之后出现了一个新问题：同一条要求散落在多个会话里，每次理解可能都不一样。最典型的一次，是我按早期会话里的说法改了一个约定，而那个说法在更晚的会话里已经被推翻了，只是没人记得。

做法是立一份"需求总账"：批量回查历史会话，把提过的要求全部抽出来，去重后写成唯一一份，并给它加上状态字段。

| 要求 | 来源 | 状态 | 依据 |
| --- | --- | --- | --- |
| 全站时间口径统一为"半年" | 早期会话 | 生效 | 站点文案检查清单 |
| 失败的实验也要完整归档 | 中期会话 | 生效 | 实验记录模板 |
| 早期约定的某个目录结构 | 早期会话 | 已被取代 | 后期改为按产物类型分目录 |

抽取出来的原始条目有两百多条，大部分是重复表述，去重并标注状态之后收敛到几十条。**总账的价值不在"列出要求"，而在把"已失效"的那部分显式标出来**——否则它只是新增了一份会过期的文档。

## 二、规则文件与记忆文件的分工

| 文件 | 写什么 | 不写什么 | 更新时机 |
| --- | --- | --- | --- |
| 规则文件 | 环境约束：哪些命令不能用、哪些路径要转义、交付前必跑什么 | 项目介绍、一次性任务 | 每次踩到新坑 |
| 记忆文件 | 结论：被否掉的方案、不适用的参数范围、决定背景 | 过程流水账 | 得出结论的当次 |
| 需求总账 | 要求的唯一表述 + 状态 | 未确认的猜测 | 会话数明显增长后 |

判断一条信息进哪本账，问一句：**它是环境属性，还是会随任务变化？** 环境属性写规则，任务相关写记忆。

一条真实收益：Windows 下路径转义的约束，写进规则文件之前，我在五次会话里重复解释过五次；写进去之后，这个问题再没出现过。写一行的时间，换掉后面所有的重复排查。

## 三、跨设备：把记忆放在工具之外

多台设备上用的是不同的智能体框架。如果记忆只存在于某个客户端里，换设备就等于失忆。所以记忆与经验以文件形式放在项目目录，再用一个私有仓库在设备之间同步：

```bash
git -C ~/agent-memory pull --rebase
git -C ~/agent-memory add -A
git -C ~/agent-memory commit -m "rules: 追加路径转义约束"
git -C ~/agent-memory push
```

这条约束决定了长期使用体验：**换框架的成本大幅下降**，因为真正的资产（规则、结论、方法）不在框架里，要迁移的东西本来就不多。

::: tip 性价比最高的一步
在会话结束前多问一句：今天有没有出现新的"下次不该再犯"的事？有就写一行进规则文件或记忆文件。这一步几乎零成本，但它决定这套协作是积累还是重复。
:::

## 四、判断标准：下次它会自动起作用吗

写完一条经验，我会问：**下次遇到同样的事，它会自动起作用吗？**

- 答案是"要我自己想起来去翻文档"——这条经验迟早失效；
- 只有当它被放在"每次都会被读到"的位置（规则文件、检查清单、自动化脚本），它才算真正变成了制度。

同一个判断也适用于技能与流程：写进[技能](/notes/skill-design)的触发条件，是给智能体读的规则；写进规则文件的约束，是给每次会话读的规则。两者都要求一点：**位置比内容重要**。

::: warning 容易踩的坑
把经验写进聊天记录或存在某个客户端里，看起来也"记下来了"，但它不会在下一次自动出现。出现一次是意外，出现两次就是流程缺了一条规则。
:::

## 五、可复用的清单

- 规则文件只写环境约束，记忆文件只写结论，需求总账只写要求的唯一表述；
- 总账必须带状态字段，把"已被取代"的条目显式标出来；
- 汇总历史要求时用智能体批量回查，比人工回忆准确；
- 记忆与规则以文件形式放在项目目录，通过私有仓库跨设备同步；
- 每写完一条经验，自问它会不会在下次自动生效；
- 同一个问题出现两次，就把它升级成规则、检查项或脚本。
