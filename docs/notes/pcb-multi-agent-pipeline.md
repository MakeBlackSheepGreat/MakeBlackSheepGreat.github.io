# 让多智能体做硬件设计：一条从拓扑讨论到出货的流水线

> 2026 年 7 月。硬件设计与软件最大的差别在成本结构：**出错贵、反馈慢**，走完一轮打样要几周。"先想清楚再动手"在这里不是风格问题，而是成本问题。

::: info 先说结论
- 阶段化的价值不在"分工好看"，而在把**前置产物**变成硬门槛：原理图未冻结，就不进布局；
- 最反直觉的一条：硬件里**并行的收益很有限**。试过让不同会话同时改原理图和布局，结果是布局按旧封装布线，改一次封装要重布 8 个网络；
- 检查点必须是不可绕过的：配置里没有"跳过"选项，只有"停下"和"修好再跑"。
:::

## 一、最初的方案：照搬软件里的并行

场景是一块非商业用途的控制板，从拓扑讨论一直做到导出制造文件。最初的想法很自然——软件项目里多智能体并行能直接换来速度，硬件也照做：一个会话讨论器件选型，一个先起原理图，一个按"大概的布局"先布板。

第一轮的产出是这样：

| 现象 | 直接后果 |
| --- | --- |
| 选型阶段改了器件封装（换成更易采购的同类封装） | 布局里 8 个网络要重布 |
| 布局文件引用的原理图版本，与当前版本不是同一版 | 网络表对不上，只能回退重做 |
| 三个会话各有一份自认为"最新"的物料清单 | 谁也不知道该以哪份为准 |

我把第一轮的返工点按时间线排开，几乎每一条都能追到同一个原因：**下一阶段在前置产物冻结之前就开工了**。软件里编译错误是秒级反馈，硬件里要等一轮打样——同样是"改一下"，代价差几个数量级。

## 二、改成阶段化流水线

改法是把流程切成阶段，每个阶段有明确的输入与产物，**上一阶段的产物是下一阶段的前置条件**：

| 阶段 | 输入 | 产物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 拓扑与选型 | 需求与约束 | 拓扑说明、器件清单（含封装与可购性） | 器件封装冻结 |
| 原理图 | 拓扑与器件清单 | 原理图、网络表 | 电气规则检查通过 |
| 布局布线 | 原理图与网络表 | 布局文件、布线结果 | 约束检查通过 |
| 制造输出 | 布局文件 | 制造文件（非商业用途） | 下单前 BOM 人工复核 |

这样拆的两个收益：每次只让智能体关注一个阶段的目标，不会出现"一边改电路一边改布局"的互相干扰；出问题时能定位到具体阶段，而不是"整条流程都有问题"。

## 三、9 个技能模块，而不是一段长提示词

流程被拆成 **9 个技能模块**，每个模块负责一类工作：器件参数核对、网络表检查、布局约束整理、制造文件检查等。模块化的直接收益是**可以单独验证**——拿一份网络表单独跑检查模块，植入几个已知错误，看它能不能全找出来，不必等整条流程跑完再看结果。

工具侧通过 MCP 驱动 EDA 软件，让智能体真的读取和修改设计文件，而不是"给出建议后由人手工操作"。这一点决定了流水线是自动的还是一半靠人搬。

## 四、两个不可绕过的设计

**硬性检查点。** 电气规则检查、封装核对、器件可购性核对被写成流程里不可跳过的关卡——配置里干脆没有"跳过"这个选项：

```yaml
gates:
  - id: erc
    run: skills/erc_check
    on_fail: stop          # 只有 stop 与 fix_and_rerun，没有 skip
  - id: footprint_audit
    run: skills/footprint_check
    on_fail: stop
```

硬件不像软件，一个封装错误的代价是整批板子报废，所以"看起来没问题就跳过"这个选项本身就不该存在。

**人工确认点。** 流程里明确标出必须由人确认后才能继续的环节：方案冻结、下单前的 BOM 复核。把"人该在哪里介入"写进流程配置，比指望智能体自己判断边界可靠。

## 五、与软件流水线的差别

软件里多智能体并行通常直接换来速度；硬件里**串行依赖太强**——选型不定，原理图收敛不了；原理图不定，布局无从谈起。并行的空间只存在于少数输入已经冻结的工作上（例如同时核对多个器件的可购性）。

这个项目更清楚的结论是：多智能体不是加速器，它的价值取决于任务能不能被安全地切开，以及每一段的产物能不能被独立验证。衡量收益的指标也跟着变了——不是"省了多少设计时间"，而是"省了几轮打样"。

::: tip 性价比最高的一步
把"前置产物冻结"做成流程里的显式事件：冻结后产物带版本号，下游阶段引用版本号而不是文件名。这一步几乎不花时间，却消掉了最常见的一类返工。
:::

::: warning 稍加注意
不要在硬件流程里照搬软件式并行。能否并行的依据是"两边的输入是否都已冻结"，而不是"看起来是两块独立的工作"。
:::

## 六、可复用清单

- 先按产物切阶段，再谈智能体分工；
- 每个阶段写清输入、产物、通过条件与人工确认点；
- 检查点写成硬门槛，配置里不提供跳过选项；
- 产物带版本号，下游引用版本而不是文件名；
- 只在输入已经冻结的环节使用并行；
- 用"省下几轮打样"衡量收益，而不是"省下多少设计时间"。
