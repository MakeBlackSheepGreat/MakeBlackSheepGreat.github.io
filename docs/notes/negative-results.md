# 负面结果也是一份结果

> 我做了一个模块，实验前认为它会让模型更准。实验后它把准确率从 77.23% 拉到了 56.78%。

::: info 先说结论
- 最值钱的反转不是"模块没用"，而是**崩坏的信号不在 loss 上**：训练全程 loss 都在正常下降，模型实际上已经放弃了大部分特征；
- 事先写下的判定标准把"56.78%"从"再调调参说不定就好了"变成了一条可以直接执行的失败判定，节省的是无限期的拖延；
- 结论：问题出在设计上（路由归一化会自我强化），不是学习率或初始化能解决的。
:::

## 一、背景：一个看起来很有道理的模块

基线模型在图像分类任务上稳定在 77.23%，先把这个数字固定下来作为对照。然后设计了一个新的注意力路由模块，思路是让模型对不同尺度的特征动态分配权重——论文里常见的做法，逻辑上也说得通。

动手之前把判定标准写了下来：**在同一套数据划分、同一个评估协议下，如果新模块不能带来稳定提升，就判定为失败，不做任何事后调整。** 当时觉得这一步有点形式主义，但还是做了。

## 二、结果：两版都崩了

| 配置 | 最好准确率 | 说明 |
| --- | --- | --- |
| 基线 | 77.23% | 稳定收敛 |
| 新模块（第一版） | 56.78% | 训练在第 61 个 epoch 崩坏 |
| 新模块（改进版） | 更低 | 第 34 个 epoch 就崩了 |

第二版改得更激进，崩得也更早。到这里，方向的问题已经很清楚。

## 三、排查：loss 一直在降，指标却在掉

最先看的是 loss 曲线——它从头到尾都在正常下降，没有任何异常尖峰。这是最容易被误导的地方：如果按"loss 正常就说明训练健康"来判断，这个模型会被认为在正常收敛。

第二个观察是指标曲线：准确率在第 61 个 epoch 前后从 70% 多直接掉到 56% 附近，而 loss 没有对应跳变。两者背离，说明模型输出的分布变了，但拟合的目标函数没有变差。

第三个观察是路由权重的分布随训练的变化。证据在这里出现了：训练早期，模块就把绝大部分权重集中到极少数通道上，剩下的通道权重几乎不再更新。**网络还在跑，loss 还在降，但模型已经放弃了大部分特征**——所谓"动态分配权重"退化成了"只用一个通道"。

这正是我在查看路由权重分布而不是只看 loss 之后才发现的，也说明：**判断训练是否健康，要看的量必须和设计意图对应。** 我加了路由，就该盯路由的权重分布，而不是盯 loss。

## 四、根因：归一化方式会自我强化

问题不在学习率也不在初始化，而在设计：我给路由加了一个会自我强化的归一化方式。某个通道只要稍微占优，就会被放大成绝对优势，其余通道的梯度随之消失——一旦进入这个状态，训练自己走不出来。

这解释了两版都崩、且更激进的一版崩得更早：改动放大了同一个机制。

::: warning 容易踩的坑
"训练崩坏"的常见解释是超参数问题，但先要问的是：**这个模块的设计里有没有自我强化的结构？** 归一化、门控、竞争性激活都容易产生"赢者通吃"，而它们在 loss 上往往看不出来。
:::

## 五、这次失败为什么比一次成功更值钱

1. **它证明了评估协议有用。** 如果事前没写下判定标准，"56.78%"很容易被解释成"再训久一点就好了"，然后无限期拖下去。
2. **它给出了可复用的诊断路径。** "权重塌缩"这个现象，以及定位它的方法（看权重分布随训练的变化，而不是只看 loss），后来在别的模型上又用过。
3. **它让后面的人少走弯路。** 失败配置、崩坏的 epoch、第二版为什么更早崩，都写进了实验记录。

::: tip 性价比最高的一步
在实验记录里固定一列"这次要看哪个量来判断健康"，并且这个量必须和设计意图直接对应。只看 loss 会漏掉整整一类失败——它们从头到尾都不报错。
:::

## 六、可复用的清单

- 判定标准写在实验开始之前，写在一个不想改就不方便改的地方；
- 监控指标要和设计意图对应：加路由就看权重分布，不是只看 loss；
- loss 正常不等于训练健康，指标与 loss 背离时优先信指标；
- 对可能"赢者通吃"的结构（归一化、门控、竞争性激活）提前设计检查点；
- 失败实验和成功实验用同一套记录格式，不写"试了不行"这种话；
- 结论只写实验能支撑的部分，"看起来有效但没验证"一律标注为未验证。
