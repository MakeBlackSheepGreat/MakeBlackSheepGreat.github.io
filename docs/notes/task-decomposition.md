# 把问题拆成智能体能执行的任务

> 用智能体做事的效率差异，绝大多数不出在模型上，而出在任务是怎么交出去的。同一个模型，收到"帮我优化一下这个项目"和收到一份写清判定的任务清单，产出质量能差出一个量级。

::: info 先说结论
- 拆解的目标不是"分得细"，而是**每个执行单元都有可独立判断的产出**；
- 拆之前先找**判定标准**：说不清"做完是什么样"的需求，拆了也没用；
- 并行度的上限不由任务数量决定，而由**是否存在共享可变状态**决定；
- 代价最大的一次返工不是因为模型选错方案，而是任务里只有目标、没有判定。
:::

## 一、返工现场：一句话需求跑了两小时

2026 年 8 月的语料流水线，第一次派发的任务描述只有一句：把这些论文整理成一个能检索的知识库。当时的判断是"智能体自己会规划"，先跑起来看效果。

跑到第二小时（约 5,500 篇）抽检时问题才暴露：产出是每篇一段自由摘要，回答不了最初要解决的问题——这条结论出自哪篇论文的哪一部分。人工核对 50 篇，能回溯到原文位置的不足 15 篇。

排查没花多少时间，因为原因很直接：模型没有选错方案，任务里根本没有"做完是什么样"这一项。所以推翻重来，先定判定再倒推子任务。修好之后，这条流水线连续跑 11.2 小时，处理 30,031 篇、完成 30,018 篇（99.96%），中途断网一次自动续跑，最终留下 18,125 条证据链接，每条都能指回原文位置。

## 二、四层拆解：从目标到执行单元

| 层次 | 内容 | 判断标准 |
| --- | --- | --- |
| 目标 | 要解决的真实问题 | 能用一句话说清"为什么做" |
| 判定 | 做完是什么样 | 可客观判断（测试通过 / 指标达标 / 抽样核对） |
| 子任务 | 相对独立的工作块 | 有明确输入输出，能单独验收 |
| 执行单元 | 一次派给智能体的任务 | 一次会话内可完成，失败可重试 |

最常见的错误是从目标直接跳到执行单元：目标很宏大，执行单元很具体，中间缺了判定与子任务划分，智能体只能自己猜——它猜的方向通常和你想的不一样。上一节那次返工就是跳过了第二层。

## 三、拆之前先回答三个问题

**一、做完是什么样？** 答不上来就先别拆。这一步经常暴露真正的问题：有些需求难派出去，是因为提出的人自己也没想清楚要什么。

**二、最小可验证单元是什么？** 能独立跑通、独立判断对错的最小集合。先做通一篇的端到端质量检查，确认方向对了，再放开规模。

**三、哪些绝对不能做？** 边界比产出更容易被忽略。只读、不要动某个目录、不要引入新依赖——不写清楚，智能体会按自己的判断行事，而这种"自主"往往不是你想要的。派发模板可以很短：

```text
任务：实现内容哈希幂等与任务表读写
输入：表结构定义 + 哈希函数位置
产出：同一批文件重跑不产生新记录，附测试通过条数
边界：不改解析逻辑，不新增依赖
验收：测试全绿并给出条数
```

## 四、粒度：一次能判断对错的产出

判据只有一条：**这个执行单元的产出，能不能不依赖上下文判断对错？** 能，粒度就合适；不能（例如"优化了一部分代码"），说明还没拆到位，或者判定缺失。

反过来，拆得过细同样浪费：把连续的工作切成十个需要来回交接的碎片，交接成本会超过收益。三种情况不拆——单文件的小改动、判断类问题（直接问比拆更省）、探索性工作（先让它自己看，再决定要不要拆）。

## 五、串行与并行由依赖决定

- **数据依赖**：后一步要用前一步的产出，必须串行；
- **接口未定**：并行改同一个接口会互相冲突，先定接口；
- **共享可变状态**：多个执行单元改同一份文件或同一份数据，要么串行，要么先隔离。

第三种最容易忽略：两个子任务同时改同一批文件，合并时互相覆盖，而每一步单独看都是对的，检查点发现不了。

::: warning 容易踩的坑
并行的前提是"互不触碰同一份可变状态"，不是"看起来独立"。派发前先列出每个单元会写哪些文件，有交集就串行。
:::

## 六、三种反复出现的拆解错误

**按工种拆，而不是按产出拆。**"一个写后端、一个写前端"只有在接口已定时才成立；按产出拆是先定接口（一个执行单元），再分别实现。

**把探索和实现塞进同一个子任务。** 探索需要穷举和试错，实现需要收敛。放在一起，智能体会用实现的心态做探索，过早锁定第一个看起来可行的方案。

**给子任务拖一大堆无关上下文。** 无关历史会稀释判断质量，只给它需要的输入。

::: tip 性价比最高的一步
派发前用一句话写下这个子任务的"完成定义"。写不出来，说明还没想清楚——这时候发出去，大概率要返工。
:::

## 七、可复用的清单

- 需求进来先问"做完是什么样"，答不上来就先定判定；
- 四层走完再派发：目标 → 判定 → 子任务 → 执行单元，不跳层；
- 每个执行单元都要能独立判断对错，判断不了就是粒度或判定缺失；
- 派发模板四行：输入、产出、边界、验收；
- 并行前比对"会写哪些文件"，有交集一律串行；
- 单文件小改、判断类问题、探索性工作不拆。
